# Nolan 採用サイト 企画・設計ドキュメント（Phase 0〜2 記録）

`sakuyalabs_portfolio_plan.md` の「⑥採用サイト｜デザイン×UX×情報設計×コピー」案件を、実装前に定義した内容の記録。

## Phase 0｜要件定義・ペルソナ設計

### 架空クライアント
- SaaSスタートアップ「Nolan」（BtoB SaaS、エンジニア採用に力を入れている想定）

### エンドユーザーペルソナ
- 転職検討中のミドルエンジニア（20代後半〜30代）。
- カルチャーフィットと裁量権を重視する。求人票の職務内容だけでは判断できない「働く実感」を求めている。
- 「良い会社です」という抽象的な自己アピールには懐疑的で、具体的なエピソード・固有名詞にこそ説得力を感じる。

### ゴール（CV地点）
- 求人へのエントリー（応募フォーム送信）

### 成功指標（KPI）
1. 職種別求人一覧から求人詳細への遷移率
2. 求人詳細からエントリーページへの遷移率

## Phase 1｜情報設計（IA）

### サイト構成（複数ページ。個々の求人・メンバーインタビューが単独で共有される前提でURLを分離する）
| # | ページ | このページの仕事 |
|---|---|---|
| 1 | TOP (`/`) | ミッション・ビジョンを一枚で伝えるヒーロー。各セクションへの導線を一覧させる |
| 2 | 求人一覧 (`/jobs`) | 職種別（エンジニア／デザイナー／PM）のフィルタ付き求人一覧 |
| 3 | 求人詳細 (`/jobs/[slug]`) | 個々の求人の詳細。SNS等での個別共有を想定し、独立したURLを持つ（SSG） |
| 4 | メンバーの声 (`/members`) | 職種の異なる複数名のインタビュー全件 |
| 5 | エントリー (`/entry`) | 応募フォーム |

### TOPページのセクション構成
Hero → Culture（バリュー、エピソードで具体化） → Member's Voice（抜粋） → 働き方（制度・環境） → 仕事内容（求人抜粋） → 選考フロー → 最終CTA（エントリー）

### 導線設計
- 求人一覧（`/jobs`）から求人詳細（`/jobs/[slug]`）、そこからエントリー（`/entry`）という一直線の導線を軸にする。
- TOPページのMember's Voice抜粋・仕事内容抜粋は、それぞれ`/members`・`/jobs`と同じデータソースを参照し、一覧ページへの「もっと見る」導線を持つ（④⑤で確立したデータ一元化の方針を踏襲）。

## Phase 2｜デザインシステム定義

- トンマナ：本音・裁量・テック感（①〜⑤とは対照的に、この案件で初めてダークモードを基調にする。エンジニア向けの
  プロダクト然としたトーンを、採用サイト自体で体現する）
- カラーパレット：
  - Primary（漆黒に近いインク）: `#0B0B14`
  - Secondary（淡い紫白）: `#F4F3FF`
  - Accent（ヴァイオレット、SaaSブランドらしい鮮やかさ）: `#7C5CFF`（装飾・非テキスト用途）
    - 明背景でのテキスト用: `#5329FF`（paper上でコントラスト比6.11）
    - 暗背景でのテキスト用: `#8C70FF`（ink上でコントラスト比5.48）
  - Neutralは`ink`から派生したグレースケール
  - 配色は実装着手前にコントラスト比を計算し、明背景用・暗背景用のトークンを最初から分けて設計する
    （③FORGE以降の標準方針）
- タイポグラフィ：見出し欧文 Space Grotesk（幾何学的でプロダクト然としたテック感を出す）、見出し和文・本文
  Noto Sans JP。①〜⑤で使ったことのないフォントペアリングにし、SaaSプロダクトのUIらしい質感を出す
- 余白の基準：8pxグリッド／セクション間 96px
- コンポーネント方針：角丸はやや大きめ（12px程度、SaaS UIらしい柔らかさ）。ホバーはヴァイオレットの発光感
  （box-shadowの淡いグロー）を使う。①〜⑤より「プロダクトのUI」に近い操作感を意識する
- 見出し（h1〜h6）の末尾に句読点を付けない（sakuyalabs_web_portfolio_project全案件共通のルール。
  ④・⑤のレビューで指摘を受け、以降の全案件に適用する標準ルールとなった）

## 技術スタック
- Next.js 16 (App Router) / TypeScript / Tailwind CSS v4（CSS-first設定）
- 求人データは④・⑤で確立したCMS移行想定のスキーマ設計（型定義とデータ取得関数の分離）を踏襲する
- `/jobs`の職種フィルタはクライアント側`useState`で実装（⑤の`/works`と同じパターン）
- `/jobs/[slug]`は`generateStaticParams`によるSSG（④の`/fields/[slug]`、⑤の`/news/[slug]`と同じパターン）
- アニメーション：Framer Motion。Cultureセクションはスクロールに応じたバリューの視覚化アニメーションを
  実装する（企画書⑥の技術ポイント）
- フォーム：React Hook Form + Zod（エントリーフォーム）
- ビジュアル素材：①〜⑤と同じ方針。写真は使用せず、CSS/SVGの抽象ビジュアル（グリッド・ノード状の線）で
  プロダクトのUIらしい質感を表現する

## ①〜⑤との差別化ポイント（意思決定ログ）
- **この案件で初めてダークモードを基調にする**：①〜⑤はすべて明るいトーンを基調（①②③は暗いHeroのみ、
  ④⑤は終始明るい）だったが、⑥はサイト全体をダークトーンで統一する。エンジニア向けプロダクトの
  UIらしさを、採用サイト自体のトーンで体現する。
- **コピーライティングを技術的な見せ場にする**：企画書⑥のアピールポイントの核心。「風通しの良い職場です」
  のような抽象論では終わらせず、Cultureセクションの各バリューに必ず社員の固有名詞・行動エピソードを
  添える設計にする（`values.ts`のスキーマ自体に`episode`フィールドを持たせ、抽象論だけのバリュー定義を
  データ構造上できないようにする）。
- **求人・メンバーインタビューを個別URLで独立させる**：④・⑤で確立した「詳細ページのみSSG」の
  パターンを踏襲しつつ、⑥では求人（`/jobs/[slug]`）が対象になる。SNS等での個別共有を前提とした
  採用サイトの実務に即した設計判断。

### Lighthouse（`--throttling-method=provided`、SakuyaLabs External Intelligence PAT-004）
| ページ | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| TOP (`/`) | 100 | 100 | 100 | 60 |
| 求人一覧 (`/jobs`) | 100 | 100 | 100 | 60 |
| 求人詳細 (`/jobs/backend-engineer`) | 100 | 100 | 100 | 60 |
| メンバーの声 (`/members`) | 100 | 100 | 100 | 60 |
| エントリー (`/entry`) | 100 | 100 | 100 | 60 |

SEOが60なのは`layout.tsx`の`robots: { index: false, follow: false }`による意図的なnoindex設定が原因（`is-crawlable`監査のみ失格）。Concept Project（実在しない架空案件）のため検索エンジンにインデックスさせない方針であり、想定通り。

### 発見・修正した問題
- **コントラスト不足（Accessibility 96→100に修正）**：`--color-ink-400`（#6F6A87）を`<dt>`ラベル・パンくずリンク・`aria-live`件数表示のテキスト色として使っていたが、`ink`（#0B0B14）上で3.81、`ink-800`（#15131F）上で3.57しかなく、通常テキストの基準4.5:1を下回っていた。`--color-ink-300`（#8F8AA3、ink上5.91／ink-800上5.53）を新設し、実際に読ませるテキストは全てこちらへ置き換え。`ink-400`はplaceholder等の非本文装飾用途に限定する運用に改めた。
  - **教訓**：配色トークンをコントラスト計算済みで用意しても、後から追加した「ちょっと薄いグレー」的な用途のトークン（ink-400）を本文用に流用すると計算対象から漏れる。二番目以降に増やすニュートラルトーンも、追加した時点でコントラスト計算をセットで行うべきだった。
- **opengraph-image.tsxの`edge` runtime指定**：Next.js 16でdeprecated警告が出た上、静的生成が無効化されていた（ビルド出力が`ƒ`表示）。`export const runtime = "edge"`を削除し、デフォルト（Node.js runtime）に戻すことで静的生成（`○`表示）に復帰。

### レスポンシブ
- `resize_window`ツールが本環境で不安定（環境既知の制限、④・⑤でも記録済み）なため、コード監査で代替：
  - 複数列グリッド（`grid-cols-`）は全て`grid-cols-1`ベースに`sm:`/`lg:`を重ねる実装になっていることを`grep`で確認（唯一の例外は求人詳細ページの`dl`用固定2列グリッド`grid-cols-[6rem_1fr]`で、これはラベル・値の対応関係を保つ意図的な固定列数）。
- `<dl>`は全箇所でdt/ddを直下に配置し、divでラップしていないことを確認（①NAGI Phase 5の反省点）。
